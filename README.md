# ChatGPT AutoPilot

ChatGPT 웹에서 **플러그인(앱·MCP 커넥터)으로 실제 작업을 시키는 사람**을 위한 Chrome 확장 프로그램입니다. 응답이 끝날 때마다 정해 둔 후속 프롬프트를 대신 입력·전송해 주어, "다음 단계 진행해"를 계속 눌러 줘야 하는 반복 작업을 **브라우저 안에서 반자동으로** 이어 가게 합니다. (실험용, v0.3.1)

> ⚠️ **전제 조건:** 이 확장 프로그램은 스스로 파일을 읽거나 코드를 실행하지 않습니다.
> ChatGPT 대화에 **작업용 플러그인이 연결되어 있고, 그 플러그인으로 작업할 대상(프로젝트 폴더 등)을 이미 가리킨 상태**여야 합니다.
> 실제 작업은 ChatGPT가 플러그인의 도구로 수행하고, AutoPilot은 그 대화에 후속 프롬프트를 넣어 주고 멈출 때를 판단할 뿐입니다.

## 이런 경우에 씁니다

- 파일 읽기·수정, 테스트 실행, git 커밋이 가능한 플러그인으로 **프로젝트를 단계별로 개발**할 때
- 목록에 있는 항목을 하나씩 처리하는 **반복 작업**(문서 정리, 에셋 생성, 데이터 가공 등)을 맡길 때
- 응답을 기다렸다가 같은 지시를 다시 보내는 일을 사람이 하지 않고, **멈춰야 할 때만** 확인하고 싶을 때

## 동작 방식

```
[사이드 패널: 시작] → 후속 프롬프트 전송 → ChatGPT가 플러그인 도구로 한 단계 작업
        ↑                                                  ↓
  AUTOPILOT: CONTINUE ← 응답 마지막 줄 확인 ←── 응답 종료 감지
        (DONE / BLOCKED / 상태 줄 없음 → 중지)
```

1. 사이드 패널에서 **시작**을 누르면 후속 프롬프트를 ChatGPT 입력창에 넣고 전송합니다. 이미 응답 중이면 끝난 뒤에 보냅니다.
2. 응답 종료는 ChatGPT의 중지(■) 버튼이 사라지고, 화면의 응답 텍스트가 몇 초간 더 바뀌지 않는 것으로 판단합니다. 도구 호출 사이에 버튼이 잠깐 사라지거나 마지막 줄이 늦게 그려져도 오판하지 않습니다.
3. 응답 마지막 줄의 `AUTOPILOT:` 상태를 읽어 계속할지 멈출지 정합니다. 화면의 HTML 구조가 아니라 **보이는 텍스트**를 기준으로, 방금 보낸 프롬프트 이후에 **한 줄 전체가** `AUTOPILOT: CONTINUE`(또는 `DONE`/`BLOCKED`)인 줄만 상태로 인정합니다.
4. 계속이면 **같은 프롬프트**를 다시 보냅니다. 프롬프트가 "현재 상태를 확인하고 다음 항목 하나를 하라"는 내용이면, 몇 번을 반복해도 매번 다음 단계로 나아갑니다.

## 준비

| 항목 | 내용 |
| --- | --- |
| 작업용 플러그인 | ChatGPT에 앱(플러그인·MCP 커넥터)으로 연결되어 있고, 원하는 작업(예: 파일 읽기·쓰기, test/build 실행, git 커밋)을 할 수 있음 |
| 대상 | 플러그인이 접근할 수 있는 프로젝트 폴더나 작업 공간 |
| ChatGPT 대화 | 입력창에서 플러그인을 선택하고, 어느 대상에서 작업할지 한 번 알려 둔 상태 |
| (권장) 진행 상황 문서 | 개발이라면 `ROADMAP.md`, `PROJECT_STATE.md`, `tasks/TASK-XXX/{SPEC,TODO,QA,RESULT}.md`. 없으면 기본 프롬프트가 첫 단계에서 만들게 합니다 |
| Chrome | 116 이상 (사이드 패널 API) |

## 설치

1. 저장소를 `git clone`하거나 ZIP으로 내려받아 압축을 풉니다.
2. Chrome에서 `chrome://extensions`를 열고 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램 로드**를 눌러 `manifest.json`이 있는 폴더를 선택합니다.
4. 툴바의 퍼즐 아이콘에서 ChatGPT AutoPilot을 **고정(📌)** 해 두면 편합니다.

업데이트 후에는 `chrome://extensions`에서 새로고침(↻)하고, 열려 있던 ChatGPT 탭도 새로고침하세요.

## 사용법

1. 플러그인으로 작업 대상을 가리켜 둔 ChatGPT 대화를 엽니다.
2. 툴바의 AutoPilot 아이콘을 누르면 **오른쪽 사이드 패널**이 열립니다. 페이지의 다른 곳을 클릭해도 닫히지 않습니다.
3. 패널의 **시작 전 확인** 항목을 점검합니다.
4. 후속 프롬프트(기본값 그대로 써도 됨)와 최대 전송 횟수를 확인하고 **시작**을 누릅니다.
5. 패널의 상태·진행률·로그에서 진행 상황을 봅니다. 언제든 **중지**할 수 있고, 멈춘 뒤 다시 **시작**하면 이어서 진행합니다.

프롬프트·횟수·옵션은 자동 저장되며, **기본값으로 되돌리기**로 기본 프롬프트를 복원할 수 있습니다.

## 후속 프롬프트 작성법

후속 프롬프트는 **매번 똑같은 문장**이 전송됩니다. 그래서 다음 두 가지를 지키면 오래 안정적으로 돕니다.

1. **대화 기억이 아니라 저장된 상태를 기준으로 판단하게 합니다.** 예: "파일과 git 상태를 확인하고, 미완료 항목 중 가장 앞선 것 하나만 처리하라." 중간에 대화가 끊기거나 길어져도 같은 문장으로 이어집니다.
2. **응답 마지막 줄에 상태를 쓰게 합니다.** 아래 셋 중 하나를 한 줄에 단독으로 쓰도록 요청하세요.

```
AUTOPILOT: CONTINUE   ← 남은 작업이 있음, 계속 전송
AUTOPILOT: DONE       ← 모든 작업 완료, 중지
AUTOPILOT: BLOCKED    ← 남은 모든 작업이 사람을 기다림, 중지
```

자리를 비우고 오래 돌릴 때는 프롬프트에 **"사람 입력이 필요한 항목은 기록하고 건너뛰어라, BLOCKED는 바꿀 수 있는 파일이 하나도 없을 때만 써라"** 를 넣어 두세요. 그렇지 않으면 맨 앞 작업 하나가 사람을 기다린다는 이유로 첫 회부터 멈출 수 있습니다. 기본 프롬프트에는 이 규칙이 들어 있습니다.

프롬프트 안에서 이 선택지를 안내할 때는 `AUTOPILOT: CONTINUE  (남은 작업이 있음)`처럼 **뒤에 설명을 붙이세요.** 설명이 붙은 줄은 상태로 인식하지 않으므로, 보낸 프롬프트 자체를 응답으로 오인하지 않습니다.

### 기본 프롬프트

기본값은 **프로젝트 개발용**이며 특정 플러그인의 도구 이름에 의존하지 않습니다. 전문은 [`src/defaults.js`](src/defaults.js)에 있습니다.

- `git status`와 진행 상황 문서로 현재 상태 파악, 커밋 안 된 변경이 있으면 먼저 마무리
- 미완료 항목 중 **지금 진행할 수 있는 가장 앞선 것 하나**를 구현하고, 프로젝트의 test/build로 검증
- 사람의 입력(플레이테스트, 피드백, 디자인 결정, 키·계정 등)을 기다리는 항목은 "사람 확인 필요"에 적고 **건너뛰어 다음 항목을 진행**. 같은 이유로 두 번 실패한 항목도 같은 방식으로 건너뜀
- 통과하면 문서를 갱신하고 바뀐 파일만 로컬 커밋
- TASK가 다 끝났거나 모두 막혔으면 ROADMAP 마일스톤을 TASK로 쪼개고, 그것도 없으면 테스트·버그·문서 같은 근거 있는 개선 작업을 진행 (새 기능은 BACKLOG에 제안만)
- 원격 push·대량 삭제·배포·비밀값 처리는 하지 않고 "사람 확인 필요"로 기록
- 마지막 줄에 `AUTOPILOT:` 상태 표기

개발이 아닌 반복 작업이라면 같은 원리로 바꿔 쓰면 됩니다. 예: "`QUEUE.md`에서 상태가 `pending`인 첫 항목 하나를 처리하고 `done`으로 바꿔라. `pending`이 없으면 `AUTOPILOT: DONE`."

## 자동 중지 조건

| 조건 | 패널 표시 |
| --- | --- |
| 응답 마지막 줄이 `AUTOPILOT: DONE` | 완료 |
| 응답 마지막 줄이 `AUTOPILOT: BLOCKED` | 확인 필요 |
| `AUTOPILOT:` 상태 줄이 없음 (옵션, 기본 켜짐) | 확인 필요 — 도구 승인 대기나 오류일 가능성 |
| 최대 전송 횟수 도달 (기본 10, 최대 100) | 중지됨 |
| 입력창·전송 버튼을 찾지 못하거나 전송 후 응답이 시작되지 않음 | 오류 |
| 사용자가 **중지** 클릭 | 중지됨 |

멈출 때 로그에 확장 프로그램이 읽은 응답의 끝부분과 보낸 프롬프트를 찾았는지가 함께 표시되어, 원인을 바로 확인할 수 있습니다.

## 안전 수칙

- 이 확장 프로그램은 **사람이 확인 버튼을 누르는 횟수를 줄여 줄 뿐**, 플러그인의 권한을 제한하지 않습니다. 플러그인에 넓은 권한(삭제, push, 배포 등)이 있다면 **프롬프트의 금지 규칙이 사실상 유일한 안전장치**입니다. 프롬프트를 고칠 때 이 부분은 유지하세요.
- 가능하면 반복 작업에는 **필요한 권한만 가진 플러그인**을 쓰는 것을 권장합니다. (예: 읽기, 정해진 검사 명령, 로컬 커밋만 허용)
- 처음에는 최대 전송 횟수를 2~3회로 낮춰 동작을 확인하고, 결과물(커밋 등)은 사람이 검토한 뒤 반영하세요.
- 상태 줄 확인 옵션(엄격 모드)은 끄지 않는 것을 권장합니다. 도구 승인 대기나 오류 상황에서 프롬프트를 계속 보내는 것을 막아 줍니다.

## 제한 사항

- ChatGPT 웹 UI가 바뀌면 입력창·전송·중지 버튼 감지가 깨질 수 있습니다. 여러 selector를 차례로 시도하지만 보장되지 않습니다. (응답 판독은 보이는 텍스트 기준이라 구조 변경에 비교적 강합니다)
- 페이지를 새로고침하면 실행이 끊기며, 자동으로 다시 시작하지 않습니다.
- `chatgpt.com`에서만 동작합니다.
- 로그인·CAPTCHA·사용량 제한을 우회하는 기능은 없습니다. 서비스 이용 조건에 따라 자동화가 제한될 수 있습니다.

## 프로젝트 구조

```
manifest.json        Chrome MV3 설정 (chatgpt.com 한정, 사이드 패널)
sidepanel.html       사이드 패널 UI
src/background.js    아이콘 클릭 시 사이드 패널 열기
src/defaults.js      기본 프롬프트·횟수
src/sidepanel.js     설정 저장, 시작/중지, 상태·로그 표시
src/content.js       ChatGPT 화면 감시, 프롬프트 입력·전송, 상태 줄 판독
ARCHITECTURE.md      구성 요소와 설계 원칙
ROADMAP.md           마일스톤
PROJECT_STATE.md     현재 상태와 변경 이력
tasks/               작업 단위 문서
```
