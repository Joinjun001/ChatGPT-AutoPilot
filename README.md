# ChatGPT AutoPilot

ChatGPT 웹에서 연결된 작업용 플러그인(MCP·앱)을 사용하여 프로젝트 작업을 이어 가는 Chrome 확장 프로그램입니다. **사람이 시작한 대화**에서 응답 종료 후 다음 프롬프트를 전송합니다. (실험용 v0.6.0)

> AutoPilot 자체는 코드를 실행하거나 도구 권한을 얻지 않습니다. 작업은 대화에 연결된 플러그인이 수행합니다. 최대 100회는 전송 상한이지 실제 100회 완주 보장이 아닙니다.

## 주요 기능

- **AI 생성 프롬프트(기본 모드)**: AI의 마지막 응답에서 다음 작업 지시를 추출하고 다음 회차에 전송
- **고정 프롬프트 모드**: 이전과 같이 최초 프롬프트를 반복 전송
- **최대 100회**: 전송 횟수 제한(기본 10회), 완료·차단·형식 오류 시 조기 중지
- **일시적 오류 재확인**: 클릭 이전 입력 UI 탐색과 응답 텍스트 판독을 0~3회 재확인. 클릭 후에는 중복 전송하지 않음
- **체크포인트/수동 재개**: 회차·최초/다음 프롬프트·작업 범위·응답 단계·오류 로그 저장. 새로고침 후 자동 재개하지 않음
- **반복 감지**: 정확히 같은 다음 프롬프트가 3회 연속 생성되면 중지
- **안전 규칙**: 고정 작업 범위와 매 회차 공통 지시를 덧붙임. 실제 권한 통제는 별도 플러그인에서 구성해야 함

## v0.4.2 — 기본 권한 판단과 불필요한 중단 최소화

- **현재 연결된 도구와 작업 범위에서 이미 허용된 작업**(파일 수정, 테스트, 빌드, 정상적인 프로젝트 설정, 로컬 Git 커밋)은 다시 허락을 묻지 않고 진행하도록 기본 최초 프롬프트와 매 회차 고정 안전 규칙을 수정했습니다.
- 권한 오류나 개발 환경 문제가 발생해도 허용된 방법으로 재진단·수정·검증하고, 진행할 수 없는 한 TASK만 기록한 뒤 독립적인 다른 TASK로 넘어가도록 지시합니다.
- **AUTOPILOT: BLOCKED**는 실제 외부 권한·승인이나 사람만 제공할 수 있는 필수 입력이 없고 허용된 독립 작업도 남지 않은 경우에만 출력하도록 안내합니다.
- 이전 v0.4.1의 **기본 최초 프롬프트를 수정하지 않은 경우에만** 업데이트 후 사이드 패널을 열 때 새 기본 정책으로 자동 전환합니다. 사용자가 편집한 프롬프트는 그대로 유지합니다. 매 회차 고정 규칙은 저장한 프롬프트와 관계없이 적용됩니다.
- 확장 프로그램은 OS·브라우저·연결 도구의 권한을 직접 부여할 수 없으며, 로그인·도구 승인·샌드박스·보안 검사·사용량 제한을 우회하지 않습니다. 원격 push·실배포·결제·비밀키 사용은 자동 권한 범위 밖입니다.
- **중단 자체가 완전히 사라지는 것은 아닙니다.** DONE, 사용자의 중지, 최대 전송 횟수, 반복 감지, 응답 형식 오류, 전송 여부 불확실성 등 기존 안전 정지·재개 규칙을 유지합니다.
- 서버의 소스 코드를 변경해도 PC에 설치된 확장 프로그램이 자동으로 갱신되지는 않습니다. 최신 확장 코드로 교체한 뒤 chrome://extensions에서 확장 프로그램과 ChatGPT 탭을 새로고침해야 합니다. 실행 중인 회차는 새 코드로 자동 교체되지 않습니다.





## v0.6.0 실행 추적 및 MCP 감사 로그 (사전 검증 버전)

v0.5.0의 Plan Mode와 기존 1~100회 반복 실행 기능은 유지하면서 실제 Chrome 인수 전에 진단 로그를 추가했습니다.

- 브라우저: 실행 ID, 회차, 진행 상태, 계획 단계, 작업 결과를 로컬 저장소에 최근 1,000개 이벤트까지 보관합니다. 사이드패널의 실행 추적 기록에서 JSONL 내보내기가 가능합니다.
- 실행 프롬프트: MCP 도구 exec_command/run_script에서 env 인자를 지원하면 AUTOPILOT_RUN_ID와 AUTOPILOT_TURN을 함께 전달하도록 요청합니다. AI의 도구 호출 여부에 따라 식별자가 누락될 수 있으며 모든 MCP 도구가 이를 지원하지는 않습니다.
- MCP 서버: 별도로 배포된 cokacremote 소스에 감사 로그 패치를 적용했으며 사용자 저장소의 integrations/cokacremote/audit-v06.patch에도 패치를 보관합니다. 운영 서버 프로세스는 아직 재시작하지 않았습니다.
- MCP JSONL 위치: 기본 /shared/autopilot-logs/mcp/events.jsonl (MCP_AUDIT_DIR로 변경 가능). 2 MiB 파일 로테이션과 최대 5개 이전 로그 보관.
- 기록: HTTP 요청 ID, 도구명, 처리 시간, 종료 코드, 오류 분류, 선택적 실행 ID/회차. 원본 명령, 파일 내용, stdin, 인증 헤더, stdout/stderr 원문은 저장하지 않습니다.
- 실행 요약: node scripts/audit-summary.mjs <events.jsonl> [summary.json]. 브라우저 로그와 MCP 로그를 별도로 집계합니다. 브라우저 로그가 MCP 서버로 자동 업로드되는 기능은 아직 없습니다.
- 실제 운영 적용: 정상 배포 절차에 따라 MCP 프로세스를 재시작해야 합니다. 연결 중인 프로세스를 강제 종료하지 않았으므로 현재 상시 서비스는 새 기능을 아직 로드하지 않았습니다.
- 운영 주의: 감사 로그는 Git 저장소 밖에 생성하며 파일 권한을 제한합니다. 로그 접근 권한 및 저장 공간을 별도로 관리해야 합니다.

### MCP 감사 로그 패치 재적용

해당 cokacremote 소스 버전에서 git apply --check /shared/ChatGPT-AutoPilot/integrations/cokacremote/audit-v06.patch 로 적용 여부를 먼저 확인합니다. 적용 후 npm run typecheck, npm run build, npm test를 실행합니다. 실제 운영 재배포 시에는 해당 컨테이너 이미지 및 영속 볼륨 설정까지 검증해야 합니다. 제3자 MCP 서버의 원격 저장소에 push하지 않습니다.

## v0.5.0 Plan Mode (프로젝트별 대화형 설계)

v0.4.2의 기존 수동 프롬프트·고정/동적 모드·체크포인트·최대 100회 실행을 유지하면서, 그 앞에 선택적으로 사용하는 설계 단계를 추가했습니다.

1. ChatGPT 대화에서 SSalMuk-Plugin 등 프로젝트를 읽을 수 있는 MCP를 연결합니다.
2. 확장프로그램의 프로젝트 선택에서 Project Salvager 또는 PerpDEX를 선택합니다. 다른 프로젝트는 이름과 /shared/프로젝트명 경로를 등록합니다.
3. AI 프로젝트 분석을 누르면 ChatGPT가 Git·파일·계획 상태를 조사하고, 질문 1~3개와 질문별 추천 3가지 선택지를 생성합니다. 사용자 직접 입력도 가능합니다.
4. 질문에 답하고 답변으로 개발 계획 생성을 누르면 마일스톤과 실제 결과물 중심 완료 기준을 제안합니다.
5. 내용을 검토하여 계획 확정을 클릭해야 계획 기반 개발 실행이 가능해집니다. 확정 계획과 프로젝트별 프로필은 브라우저 로컬 저장소에 저장됩니다.
6. 최대 실행 횟수(예: 50)를 설정한 뒤 계획으로 실행을 누르면 기존 동적 AutoPilot을 시작합니다. 첫 회차에는 확정 계획을 프로젝트 문서로 기록하도록 지시합니다.

### 현재 범위 및 한계

- 질문과 목표는 고정 목록이 아니라 실제 프로젝트 분석 결과에서 AI가 동적으로 생성합니다. 사용자가 승인하지 않은 계획을 자동 실행하지 않습니다.
- Plan Mode는 일반 개발 반복과 별개의 한 번짜리 대화 요청입니다. 설계 질문/계획 단계에는 파일 수정·커밋·배포를 하지 않도록 지시하지만, 이것은 프롬프트 정책이며 MCP 서버의 강제적인 읽기 전용 권한과는 다릅니다. 강제 보호가 필요하면 읽기 전용 MCP 계정·도구를 사용해야 합니다.
- 확장프로그램은 MCP 도구를 직접 실행하지 않습니다. ChatGPT 대화에서 연결된 플러그인이 필요합니다. 로그인, 권한 요청, 도구 승인, 유료 API 제한을 자동 우회하지 않습니다.
- 계획 수립 결과는 확장프로그램 로컬에 저장됩니다. 사용자 승인 후 첫 실행 프롬프트가 프로젝트 문서 반영을 요청하지만, 실제 기록 성공은 별도 검증 대상입니다.
- 설계 질문 생성 요청은 3분 안에 완성된 형식으로 회신되지 않으면 재전송하지 않고 오류로 처리합니다. 새로고침 시 진행 중이던 요청은 자동 재개하지 않습니다.
- 계획 작업과 반복 작업은 동시에 진행하지 않도록 보호합니다. 기존 수동 모드는 이전과 같이 별도로 사용 가능합니다.
- 실제 Chrome UI에서 질문 렌더링·선택·계획 확정·연속 실행까지 종단간 실사용 검증은 아직 필요합니다. npm test는 모의 DOM 테스트까지 검증합니다.
- 역할별 실제 독립 AI 병렬 실행, 이미지 생성 도구 자동 연결, 모델 사용량 측정, 상세 목표별 대시보드는 이번 v0.5.0 범위에 포함되지 않았습니다.

## 설치

1. GitHub 저장소를 clone하거나 ZIP으로 내려받습니다.
2. Chrome 주소창에서 `chrome://extensions`를 열고 **개발자 모드**를 활성화합니다.
3. **압축해제된 확장 프로그램 로드**를 눌러 `manifest.json`이 있는 폴더를 선택합니다.
4. 코드 업데이트 시 확장 프로그램을 새로고침하고 ChatGPT 탭도 새로고침합니다.

## 실행 방법

1. `chatgpt.com` 대화에서 작업용 플러그인을 연결하고 접근할 프로젝트를 먼저 확인합니다.
2. 확장 프로그램의 사이드 패널을 열고 **AI 생성 프롬프트** 모드를 선택합니다.
3. **고정 작업 범위**에 `/shared/PerpDEX`처럼 해당 프로젝트를 입력합니다.
4. 최초 프롬프트에 목표와 진행 원칙을 입력하고 최대 횟수(1~100), 재확인 횟수(0~3)를 설정합니다.
5. **시작**을 눌러 실행합니다. 그 뒤 회차마다 AI가 새 작업 지시를 출력하면 확장 프로그램이 이를 감지하고 전송합니다.
6. **중지**를 누르거나 새로고침했다면 같은 대화에서 **재개**를 누를 수 있습니다. 전송 여부가 불확실한 체크포인트는 중복 실행 방지를 위해 재개하지 않습니다.

처음 사용할 때는 2~3회만 설정해 실제 ChatGPT 화면에서 응답 완료 감지, 프롬프트 추출, 로컬 커밋을 검증한 후 늘리세요.

## AI 응답 형식

동적 모드에서 진행할 작업이 있으면 마지막 부분에 반드시 다음 형태를 출력해야 합니다. 확장 프로그램은 START와 END 사이만 다음 작업으로 사용합니다.

```text
작업 결과: 테스트 통과, 로컬 커밋 완료

AUTOPILOT_NEXT_PROMPT_START
연결된 도구로 /shared/PerpDEX의 다음 미완료 TASK를 구현하세요.
Git 상태를 읽고 검증 후 다음 프롬프트를 작성하세요.
AUTOPILOT_NEXT_PROMPT_END
AUTOPILOT: CONTINUE
```

완료했으면 응답 마지막 줄에 `AUTOPILOT: DONE`, 더는 승인 없이 진행 가능한 작업이 없으면 `AUTOPILOT: BLOCKED`를 출력합니다. 차단된 TASK가 있다면 AI는 이를 기록하고 **의존성이 없는 다른 작업**으로 전환하도록 지시받지만, 가능한 대안이 없으면 중지해야 합니다.

동적 모드에서 구분자 누락·중복·잘못된 형식·비정상적으로 긴 프롬프트는 **자동 중지**합니다. 상태 줄 없이 자동으로 전송하는 동작은 하지 않습니다.

## 동작 및 복구 원칙

- 각 메시지 시작과 끝에 회차별 고유 식별자를 포함하여 이전 대화의 응답과 섞이지 않도록 합니다.
- 전송 버튼 클릭 전에만 DOM 탐색 실패를 재시도합니다. 클릭 후 응답이 늦어져도 동일 메시지를 자동 재전송하지 않습니다.
- `chrome.storage.local`에 현재 실행의 체크포인트와 다음 프롬프트 미리보기를 저장합니다.
- 새로고침 뒤에는 같은 대화 URL과 저장된 마지막 회차를 비교하여 **사용자 클릭으로만** 재개합니다. 클릭 직전 상태처럼 전송 여부를 확정할 수 없는 경우는 재개를 거부합니다.
- 동일한 후속 프롬프트가 3회 연속 나오면 작업 무한 반복 가능성을 표시하고 중지합니다.
- 사용량 제한, CAPTCHAs, 로그인, 도구 승인 또는 보안 검증을 자동으로 우회하지 않습니다.
- 더 이상 할 일이 없는 경우 억지 TASK를 만들지 않고 `DONE`으로 종료합니다.

## 안전 경계

**고정 안전 규칙은 실제 권한 제한을 대신하지 않습니다.** 프롬프트에는 원격 push, 실배포, 대량 삭제, 결제, 키 사용, 권한 우회를 금지하도록 작성되어 있지만, 도구가 넓은 쓰기 권한을 가졌다면 그 지시만으로 강제할 수 없습니다. SSalMuk Safe처럼 읽기/검증/로컬 커밋으로 권한을 제한한 플러그인과 함께 사용하는 편이 안전합니다. 모델 출력은 신뢰할 수 없는 작업 지시로 간주해야 합니다.

## 개발자 검증

추가 패키지 설치 없이 Node.js 22에서 확인할 수 있습니다.

```bash
npm run check
npm test
```

이 테스트는 응답 프로토콜 판독과 주요 예외를 검증합니다. Chrome과 실제 ChatGPT 웹 UI의 통합 동작, 장시간 100회 안정성은 별도 수동 테스트가 필요합니다.

## 구조

```text
manifest.json         Chrome MV3 설정
sidepanel.html        모드·범위·횟수·재개 설정 및 로그 UI
src/background.js     사이드 패널 열기
src/defaults.js       최초 지시와 횟수 기본값
src/protocol.js       상태 마커·후속 프롬프트 파싱 및 회차 식별자
src/content.js        DOM 감시·입력·응답 판독·체크포인트·연속 실행
src/sidepanel.js      설정 저장 및 실행 명령
test/protocol.test.cjs  순수 함수 테스트
```

**제한:** 이 확장 프로그램은 브라우저 UI 자동화 방식이므로 ChatGPT DOM 변경, 렌더링 지연, 세션 종료, 사용량 제한의 영향을 받을 수 있습니다. 브라우저 새로고침 후 무인 자동 재시작하지 않습니다.

## v0.4.1 — 화면 안내 문구로 인한 상태 판독 실패 수정

- ChatGPT 대화의 `main.innerText`에는 AI가 작성한 마지막 줄 뒤에 `ChatGPT can make mistakes. Check important info. Latest response Thinking effort High`와 같은 화면 안내 문구가 붙을 수 있습니다.
- 응답 프로토콜 파서는 이 알려진 footer만 제거하고 `AUTOPILOT: CONTINUE/DONE/BLOCKED`를 판정합니다. 임의의 추가 내용이나 잘못된 구분자는 계속 허용하지 않습니다.
- 실제 로그 형태의 footer가 포함된 프로토콜 및 모의 DOM 연속 실행 테스트를 추가했습니다.
- 브라우저 재설치/새로고침 후 이전 작업에서 중단되었다면 같은 대화에서 `재개`를 시도할 수 있습니다. 단, 다른 메시지를 추가한 대화나 전송 상태가 불분명한 체크포인트에서는 안전하게 재개하지 못할 수 있습니다.

## v0.4.2 — Assistant 메시지 본문 우선 판독 및 화면 안내 문구 대응

- 회차별 `AUTOPILOT_MESSAGE_ID`를 가진 사용자 메시지를 기준으로 **그 뒤의 Assistant 답변만** 가져와 `AUTOPILOT: CONTINUE/DONE/BLOCKED`와 다음 프롬프트를 판독합니다. 본문에 Markdown 요소가 있으면 버튼·평가 안내 대신 해당 본문을 우선합니다.
- DOM에 메시지 역할을 식별할 수 없으면 기존 `main.innerText` 기반 방식으로 복귀하되, `Like this personality?`, `Latest response High` 등 알려진 안내 문구만 제거합니다. 임의의 추가 텍스트는 계속 엄격하게 거부합니다.
- 다른 사용자 메시지가 이미 입력된 경우 오래된 Assistant 결과를 재활용하지 않습니다. 긴 사용자 프롬프트가 접혀 끝 식별자가 없어도 시작 식별자가 있으면 해당 Assistant 결과를 검사합니다.
- 기존 프로토콜/DOM 모의 테스트에 위 실패 사례를 추가했습니다. 실제 ChatGPT DOM의 구조 변동과 배경 탭 타이머 제한은 여전히 통합 검증이 필요합니다.
- 업데이트 후 `chrome://extensions`에서 확장 프로그램을 새로고침하고 ChatGPT 대화 탭도 새로고침하세요. 기존 다운로드 폴더는 GitHub 업데이트만으로 자동 갱신되지 않습니다.
